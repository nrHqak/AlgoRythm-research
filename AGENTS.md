## 1. Что это за проект (в двух словах)

Автор — школьник выпускного класса, соучредитель/CTO платформы **AlgoRythm** (изучение алгоритмов через визуализацию исполнения кода: песочница с AST-классификатором, куррикулум по паттернам, AI-репетитор-сократик).

**Исследовательский вопрос:** улучшает ли использование классифицированного алгоритмического паттерна (two pointers, sliding window, DP, binary search, DFS/BFS...) как *структурного приора* точность автоматической локализации логической ошибки в коде новичка — против паттерн-агностичных методов?

**Гипотеза:** зная целевой паттерн, локализатор проверяет в первую очередь паттерн-специфичные точки отказа (у two pointers — условия сдвига указателей и условие остановки; у DP — база и переходы) и за счёт этого даёт выше Top-1/Top-3/Top-5 accuracy.

**Цель:** Республиканский конкурс научных проектов (РКНП, Казахстан, «Информатика», Направление II) → отбор на Regeneron ISEF, категория Systems Software (SOFT) / Algorithms.

**Главный продукт репозитория:** `RESEARCH_DOSSIER.md` — исследовательское досье ~21.6k слов по 9 блокам + синтез. Версия ISEF-уровня проекта ещё не писалась — досье это фундамент под неё.

## 3. Ход исследования — как это делалось и почему (лог размышлений)

### 3.1 Процесс
- План был: 7 параллельных субагентов по блокам. Реальность: **лимит параллельных агентов = 1**, фоновые запуски падали с "model concurrency limit exceeded". Успел отработать только субагент Блока 1 (отсюда его объём ~8k слов). Блоки 2–9 дособирал вручную сам.
- Инструменты нестабильны: WebSearch периодически падал (concurrency/quota), WebFetch таймаутил на societyforscience.org. **Рабочий fallback, который выручал: MCP web-reader (`web_reader`) на `duckduckgo.com/html/?q=...`** — даёт выдачу поиска как страницу. Некоторые ключевые находки сделаны именно через DDG-эндпоинт.
- Если будешь продолжать: начни с WebSearch, при падении сразу DDG-через-webReader, не жди пока отпустит.

### 3.2 Ключевые повороты мышления (важно понимать логику)

1. **Статья-2026 оказалась статьёй-2024.** Искали "Exploring the Effectiveness of AST Patterns for Algorithm Recognition (2026)". Нашёл: Neumüller, Sihler, Straub, Tichy — **ICCQ 2024** (IEEE, DOI 10.1109/ICCQ60895.2024.10576984), arXiv:2605.06098 — это поздняя (2026) выкладка того же текста. Инструмент называется **AlDeSCo**: DSL для AST-паттернов + каталог. F1=0.74 против 0.35 у CodeLlama на 3 алгоритмах (Fibonacci, Bubble Sort, Binary Search) из BigCloneEval. Артефакт открыт: zenodo.org/records/11217414. Следствие: цитировать как 2024, а не 2026; слабая генерализация за пределы каталога — их собственное ограничение.

2. **Охота за "Python vs Java MBFL" увенчалась полным текстом.** Yang, Mei & Yang, IJSEKE 35(07), 2025 (DOI 10.1142/S0218194025500329) — World Scientific отдал весь текст: 150+150 программ из ConDefects, все таблицы (Top-N, EXAM, операторы мутаций, корреляции Point-Biserial/Spearman). Отсюда взяты и точные бейзлайны (Python Top-5=92/150 при OP2), и методологический шаблон (worst-rank tie-breaking, 73.58% разработчиков смотрят только top-5).

3. **Декабрьская LLM-статья вытащена целиком (HTML на arXiv).** arXiv:2512.03421 (Xu et al., 2025-12-03): 13 LLM × 3 датасета × 503 программы, полные таблицы Top-1/3/5, стоимости ($0.0034–$0.49/программа, SBFL 0.83s / MBFL 38.28s), Wilcoxon-прецедент, дизайн user study. Это **самый важный источник досье**: задаёт и бейзлайны (o3: BugT Top-1 57.5%, Top-5 89.3%), и уязвимость (деградация с difficulty, over-reasoning, стоимость) — на которой строится питч проекта. GitHub артефакта: Xucranger/PLofLBFL.

4. **SCOPE не нашёлся.** Пользователь поминал "SCOPE" как MBFL-вариант — искал разными запросами, не существует под этим именем в FL-литературе. В досье помечено NOT FOUND (вероятно путаница с SIMFL/MUSE/Metallaxis/FEP). Если пользователь даст источник — вставить.

5. **Главный инсайт позиционирования — PROUST.** При проверке новизны понял: интеллектуальный предок идеи — PROUST (Johnson & Soloway, Yale, 1983–1990): библиотека планов → intention-based диагноз багов новичков. Это и хорошо (идея не с потолка, у неё родословная), и опасно (нужно чётко отстроиться: у нас — выученный классификатор паттернов + измеримый Top-K на бенчмарке, у них — рукописные планы под конкретное задание, без количественной оценки). Формулировка отстройки — в конце 07_block7.

6. **РКНП идёт в декабре, а не в феврале.** В ТЗ предполагался финал «конец февраля 2027». Официальное Положение 2024 (PDF с daryn.kz, скачан целиком): республиканский этап — **вторая декада декабря**. Февраль 2027 — видимо, финальный отбор Дарына на ISEF. В таймлайне синтеза учтены обе даты; финальная работа должна быть готова к концу ноября 2026. ⚠️ Положение 2024 — скачать свежее 2026/2027 в сентябре.

7. **ISEF-формы 2027 уже опубликованы** (sspcdn.../2027/Forms/...). Правило, которое бьёт по нам: **генеративный AI нельзя использовать для написания research plan, abstract (≤250 слов), постера и цитирований**. LLM-локализатор в проекте — объект исследования, это допустимо. Любой пилот на людях = Form 4 + IRB/SRC одобрение ДО сбора данных (самое частое нарушение по гидам фондов).

8. **BugT — почти закрытый датасет:** внутренняя OJ-сеть БUCT (Пекин, химико-технологический), выбран авторами именно ради отсутствия утечки в обучение LLM. Доступ — через артефакт GitHub/авторов. Если нужен — писать рано (долгая задержка).

### 3.3 Методологические решения, принятые по ходу (и почему)

- **Top-K + EXAM + worst-rank ties** — взяты как протокол из IJSEKE 2025, а не придуманы: обеспечивает сравнимость с существующими числами.
- **Exact McNemar как главный тест** (парные бинарные hit/miss на тех же программах) — под задачу «с приором vs без», прецеденты и альтернативы (Wilcoxon по difficulty-бинам, bootstrap CI) в 05.
- **Двухрежимная оценка приора: oracle vs predicted label** — пришло из понимания, что судьи/ревьюеры первым делом спросят «а если классификатор ошибается?». arXiv:2512.03421 с его абляциями промпта — шаблон.
- **5 плеч эксперимента** (SBFL / MBFL / LLM / LLM+приор / спектр×приор) — минимум, при котором клейм «не сравнили с X» неубьём.
- **Фильтр «≥1 passed + ≥1 failed test»** для корпуса — из Araujo 2016 (~40% новичковых программ валят все тесты, SBFL там не определён осмысленно).
- **n=300 минимум / 500 цель** — прикидка мощности для McNemar при ~15% дискордантных пар; подтверждается прецедентами (150 у IJSEKE, 503 у arXiv). Перед фиксацией — пилот на 30.
